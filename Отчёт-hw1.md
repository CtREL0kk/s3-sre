# Отчёт — клиент-серверное приложение «myS3»

## Доменная область

Приложение — S3-клиент: пользователь загружает  файлы и папки, организует их в дерево, управляет доступом к ним.

Ключевые сценарии:
- регистрация и аутентификация, роли обычного пользователя и администратора
- CRUD над файлами/папками (создание, чтение, загрузка, скачивание, переименование, перемещение, удаление)
- контроль доступа: объект `public`/`private` и персональные права (`read`/`write`) конкретным пользователям; доступ фильтруется при листинге (чужие приватные объекты не видны)
- двухрежимное подключение к S3: `full` (свой rustFS, полный CRUD) и `readonly` (внешний S3, только чтение)
- администрирование: переиндексация ссылок и синхронизация S3↔БД через защищённые admin-ручки
- визуализация дерева и графа связей между файлами по ссылкам (Obsidian-подобный режим)

## Стек реализации

- Backend - go 1.27 + фреймворк gin
- DB - PostgreSQL + драйвер pgx v5
- S3 - RustFS + aws-sdk-go-v2
- Логи - zap
- Frontend - React 19 + Vite 8 + TypeScript + Tailwind 4 + lucide-react
- Инфра - пока docker-compose

## Основные сущности доменной области

- User - пользователь: `id`, `username`, `email`, `password_hash`, `is_admin`.
  Роль `admin` даёт доступ
  к административным ручкам.
- Object - узел виртуального дерева (папка или файл): `id`, `owner_id`, `parent_id`,
  `name`, `type`, `visibility`, `storage_key`, `size`, `content_type`, `etag`.
  Видимость - `public`/`private`. При листинге объектов других пользователей приватные исключаются.
- Grant - выданное право (`read`/`write`) на объект конкретному пользователю. Грант на папку
  даёт доступ к её потомкам
- RefreshToken - refresh-токен для продления сессии.
- ObjectLink - ссылка из файла на другой объект (для графа связей):
  `source_id`, `target_id`, `target_name`.

## Соответствие методологии 12 факторов

### 1. Кодовая база 
Всё в одном репозитории

### 2. Зависимости
Все зависимости объявлены явно: `go.mod`/`go.sum` (Go), `package.json`/`package-lock.json`(Node)

### 3. Конфиг
Конфиг задается через переменные окружения(Параметры для БД, S3, самого приложения)

### 4. Сторонние службы
PostgreSQL и RustFS — присоединяемые ресурсы, доступ к ним по connection string из env. Можно заменить ресурс без изменений кода, просто поменять строку в конфиге

### 5. Сборка, релиз, выполнение
Multistage Dockerfile(билд, запуск)

### 6. Процессы
Сервис не сохраняет состояние, все данные хранятся в БД и S3

### 7. Привязка портов
Приложение самодостаточно: собственный `http.Server`, слушает `$PORT`не зависит от внешнего веб-сервера

### 8. Параллелизм
Сервис масштабируется через реплики, единая точка состояния - PostgreSQL

### 9. Утилизируемость
Быстрый старт, есть graceful shutdown

### 10. Паритет разработки/работы
Одинаковые стек технологий и для dev, и для prod - RustFS + PostgreSQL, отличие только в конфиге

### 11. Логирование
События логируются в stdout

### 12. Администрирование
Есть таска для запуска миграции бд: `make migrate`
Есть админские ручки, синхронизирующие состояние бд и s3, перестраивающие ссылки на объекты
Сделал их отдельными ручками для удобства эксплуатации
